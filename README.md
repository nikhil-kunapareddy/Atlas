# Atlas

Queryable project memory for coding agents. Use it instead of `CLAUDE.md`.

A `CLAUDE.md` is a flat file that every session loads in full, whether or not
any of it is relevant, and that goes stale the moment nobody remembers to edit
it. Atlas keeps the same knowledge in a store the agent *queries*: facts come
back when they're relevant, and agents write new ones as they learn.

It exposes one MCP server, so Claude Code, Codex, and any other MCP client
share the same memory for a repo.

```
$ atlas recall "how do we run integration tests"

 1. [fact] fact#7   pinned  10.00
    Integration tests need DOCKER_HOST set; `make itest` sets it for you

 2. [file] Makefile:22-31  project  1.00
    itest: ## run integration tests
        DOCKER_HOST=unix://$(HOME)/.colima/default/docker.sock go test ./it/...
```

## What's in the store

Two kinds of thing, in two scopes.

**Facts** are hand-written or agent-written knowledge — the part that actually
replaces `CLAUDE.md`. "Deploys go through the release pipeline, never
manually." "The `generated/` tree is regenerated by `make proto`; don't edit
it." Facts are deduplicated on write, so an agent re-learning the same thing
every session updates one entry instead of growing fifty phrasings of it.

**File chunks** are the indexed contents of folders you point Atlas at. Every
chunk carries its line range, so a result is `src/auth.py:40-72` — a span the
agent can open directly rather than re-reading the file to find it.

**Scopes** mirror how `CLAUDE.md` and `~/.claude/CLAUDE.md` already work:

| | |
|---|---|
| `<repo>/.atlas/store.db` | knowledge about this project |
| `~/.atlas/global.db` | knowledge true everywhere — your tooling habits, preferences |

Recall reads both and ranks project results above global ones.

## Install

Atlas is a command-line tool, so install it as one — **not** into a project
virtualenv. Your agent launches `atlas mcp` as a subprocess using your login
`PATH`, with no virtualenv active. If `atlas` only exists inside a venv, the
MCP server silently fails to start.

```bash
uv tool install "atlas-context[mcp]"      # recommended
```

or, equivalently:

```bash
pipx install "atlas-context[mcp]"
```

Both create an isolated environment and put `atlas` on your `PATH`. Requires
Python 3.10+.

<details>
<summary>Installing from a clone, before it's on PyPI</summary>

```bash
git clone https://github.com/nikhil-kunapareddy/Atlas
cd Atlas
uv tool install ".[mcp]"
```

Confirm it's visible the way your agent will see it:

```bash
command -v atlas      # must print a path outside any venv
atlas --version
```
</details>

The core is dependency-free — stdlib `sqlite3` with FTS5 does the retrieval.
The `mcp` extra pulls in the MCP SDK; `embeddings` is optional and covered
below.

## Quickstart

```bash
cd ~/code/your-project
atlas init                                    # create the store, index the repo
atlas remember "Tests need Redis: run make redis first" --tag testing
atlas remember "Never edit generated/ by hand" --pin
atlas recall "how do I run the tests"
```

Then register the MCP server with your agent:

```bash
# Claude Code
claude mcp add atlas -- atlas mcp
```

```toml
# Codex — ~/.codex/config.toml
[mcp_servers.atlas]
command = "atlas"
args = ["mcp"]
```

```json
// Any other MCP client
{ "mcpServers": { "atlas": { "command": "atlas", "args": ["mcp"] } } }
```

If your agent reports that the server failed to start, it almost certainly
can't find `atlas` on its `PATH`. Use an absolute path instead — `command -v
atlas` will give you one:

```bash
claude mcp add atlas -- "$(command -v atlas)" mcp
```

Atlas finds the project by walking up from the working directory looking for
`.atlas/` then `.git/`, so the same server config works across every repo. Set
`ATLAS_PROJECT` to pin it explicitly.

> The `atlas` command name collides with MongoDB's Atlas CLI. If you have that
> installed, `uv tool install` will warn you about the conflict; rename one of
> them or use absolute paths.

## The always-on layer

Pinned facts are returned by *every* recall regardless of the query. That's the
part of `CLAUDE.md` you genuinely do want loaded every time — a handful of
standing rules.

```bash
atlas remember "Never force-push to main" --pin
atlas facts --export > CLAUDE.md      # bridge back out when you need one
```

Keep it small. Everything else earns its way into context by matching the
query.

## MCP tools

| Tool | For |
|---|---|
| `atlas_recall` | search facts and file excerpts |
| `atlas_remember` | record a durable fact (deduplicated) |
| `atlas_facts` | list everything recorded — standing context |
| `atlas_forget` | delete an obsolete fact |
| `atlas_pin` | move a fact into the always-on layer |
| `atlas_index` | index a folder |
| `atlas_status` | what's currently stored |

The tool descriptions tell the agent *when* to reach for each one, and the
server ships MCP instructions that clients surface at session start.

## CLI

```
atlas init [path] [--no-index]     set up and index a repo
atlas index <path>...              index folders (external docs, other repos)
atlas reindex                      refresh everything already registered
atlas recall <query> [-k N]        search; --json, --full, --facts-only
atlas remember <text>              record a fact; --tag, --pin, --scope
atlas facts                        list; --tag, --json, --export
atlas forget <id> | pin <id> | unpin <id>
atlas status | sources [--remove PATH]
atlas embed                        build vectors (needs the embeddings extra)
atlas mcp                          run the MCP server on stdio
```

`--scope project|global` works on every command that reads or writes facts.

## Retrieval

Lexical by default: SQLite FTS5 with BM25, porter stemming, and identifier
splitting so `user authentication` matches `UserAuthenticator`. File paths are
folded into the index, so a query can hit a file named for the concept even
when the body never spells it out. This installs in seconds and runs offline.

Scoring is deliberately explainable — bm25 normalised to 0–1, then weighted:
facts beat chunks (someone chose to record them), project beats global, pinned
short-circuits to the top.

Semantic search is opt-in:

```bash
uv tool install "atlas-context[mcp,embeddings]"   # or: uv tool upgrade
atlas embed                                       # ~90MB model download on first run
atlas recall "why is this slow" --semantic
```

Vectors are stored alongside the lexical index and add a bounded cosine bonus,
so semantics reorder the lexical ranking rather than replacing it. Search is
brute-force cosine — fine into the tens of thousands of chunks; past that,
`embeddings.vector_search` is the seam where an ANN index slots in.

## Indexing

`atlas index` respects `.gitignore` by asking `git ls-files`, and falls back to
a built-in ignore list (`node_modules`, `.venv`, `dist`, …) outside a repo.
Binary files are skipped by extension and by null-byte sniff; files over 1MB
are skipped.

Reindexing is incremental — unchanged files are recognised by `(mtime, size)`
without a read, files touched but not modified are caught by digest, and
deleted files are pruned along with their chunks and index rows. Running
`atlas index` twice in a row is nearly free, so it's cheap to wire into a hook.

## Status

Working and tested — 69 tests covering chunking, incremental indexing, ranking,
dedupe, the CLI, and the MCP tools.

Not built yet: the multimodal extractors from this project's original scope
(images, audio, video). The indexer takes `path -> chunks`, so those are
additive — a new extractor behind the same interface, no schema change.

## Development

```bash
uv venv && uv pip install -e ".[mcp,dev]"
uv run pytest
```

For hacking on Atlas while also using it, install the tool copy separately —
`uv tool install --editable ".[mcp]"` keeps the `atlas` on your PATH pointed at
your working tree.
